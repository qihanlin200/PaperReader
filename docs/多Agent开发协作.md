# PaperReader 多 Agent 开发协作

## 目标与启动方式

默认使用单一 Agent 开发，不启动下列协作角色。只有用户对当前任务明确要求「采用多 Agent 开发模式」「启用多 Agent 协作」或同等意思时，才按本说明启用；一次任务的启用不自动延续到后续任务，除非用户明确要求持续采用。以下是开发协作角色，不是应用运行时的研究 Agent，也不是必须常驻的六个进程。启用后，主控根据任务范围选择角色；任务简单时可以直接完成。需要协作时，在派工消息中写明任务卡、相关文件、接口约定与交付物。受当前环境限制，主控加上同时运行的子 Agent 最多四个。

## 角色与归属

| 角色 | 负责内容 | 主要交付物 |
| --- | --- | --- |
| 主控 Agent | 理解意图，分析需求，定方案和验收条件；分派任务，协调共享接口，集成结果并向用户交付 | 任务卡、接口约定、集成变更、最终验收结论 |
| Skills 开发 Agent | PaperReader 的领域研究技能、技能清单与指令、路由和加载、技能效果验证；遵循 `paperreader/research_agent/domain_skills/README.md` | 技能定义、实现、适用条件及验证结果 |
| UI 设计 Agent | 布局、交互状态、视觉资源、主题一致性；先提供可查看的效果图，再实现 UI 表现并对照实际截图 | 效果图、UI 代码或资源、实际截图与差异说明 |
| 测试 Agent | 独立按需求验收功能、视觉、回归、数据隔离和平台边界；记录证据与未验证项 | 测试结果、截图或复现步骤、缺陷清单 |
| 阅读模式开发 Agent | 单篇论文的 PDF 阅读、选区与标注、阅读分析、笔记和追问行为 | 阅读模式功能与相关验证 |
| 研究模式开发 Agent | 研究项目、任务执行、证据与引用、Trace、研究成果和研究界面行为 | 研究模式功能与相关验证 |

主题、论文库、SQLite、模型配置、导入导出、打包等是共享能力。主控在任务卡里指定唯一负责人，必要时由该负责人先定义接口，再由阅读或研究模式开发 Agent 接入。不要因功能出现在某个模式的界面里，就擅自更改共享数据结构。

## 任务流程

1. **分析**：主控确认用户目标、现有行为、受影响模块、必要约束和可验证的完成条件。小修复只需简短记录；跨模块或高影响改动先写清方案。
2. **拆解**：每个子任务使用任务卡，至少写明目标、文件归属、输入与输出接口、交付物和验收条件。并行任务不得修改同一文件；如不可避免，改为顺序执行。派工前检查 `git status`，保留用户和其他 Agent 的未提交修改。
3. **视觉设计**：凡涉及 UI 修改，UI 设计 Agent 先产出可查看的效果图，再按图实现。效果图至少表现主要窗口或组件及关键状态，并遵循当前主题的配色、排版和控件风格。新增主题还须遵循 `docs/新增主题.md`。小范围视觉修复可用带标注的局部效果图。效果图是实施依据，不要求用户逐步批准，除非关键设计输入确实缺失。
4. **实现与交接**：阅读、研究和 Skills 开发 Agent 对各自行为负责。UI 设计 Agent 对视觉实现负责。若行为与表现需改同一文件，主控指定一位文件负责人，另一位提供接口、设计或补丁建议，由负责人合入。交接时说明改动文件、接口、已验证内容和剩余问题。
5. **独立验收**：测试 Agent 检查原需求、效果图与实际界面、正常及边界流程、相关回归。功能测试优先使用项目 `.venv` 与 `python -m unittest discover -s tests -v`，UI 自动化可用 Qt offscreen；视觉验收需对照实际截图。无法实机验证的 macOS/Windows、触控板、高 DPI 或真实模型请求须明确列为未验证，不得宣称通过。
6. **集成交付**：主控审查各角色结果，处理冲突，运行必要的最终验证，更新受影响文档，并交付改动、验证证据与限制。测试不通过时派回相应负责人修复，再复验。

派工时使用下面的简短格式，避免只给角色名而没有可执行边界：

```text
角色：
目标与完成条件：
负责文件或目录：
需遵守的接口、主题或数据约定：
交付物与验证证据：
与其他任务的依赖：
```

## 协作边界

- 主控是最终集成负责人，测试 Agent 保持独立判断；开发者的自检不能代替验收。
- 先约定跨模式数据和接口，再并行开发；禁止阅读与研究任务互相覆盖共享文件。
- 主题与绑定助手一对一，现有主题风格和角色设定遵循根目录 `AGENTS.md` 与 `docs/新增主题.md`。
- 应用内研究 Agent 的证据、引用、停止和项目隔离要求遵循 `docs/研究模式与研究Agent设计说明书.md`；开发协作 Agent 不改变这些产品边界。
- 打包、平台实机验证和发布按任务需要指定专项负责人，不另设常驻角色。
