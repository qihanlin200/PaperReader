# 服务模块

- `library.py`：SQLite 记录、PDF 内容哈希去重、原文件复制、配置原子写入。默认系统应用数据目录，可传入临时目录测试。必须在 UI 线程调用，SQLite 连接不在线程间共享。
- `network.py`：arXiv 链接归一化、100 MB 上限下载、OpenAI 兼容模型调用。下载和请求在后台线程执行；无密钥日志，不将服务端错误正文展示给用户。HTTP 仅允许本机模型接口，其余 API 使用 HTTPS。

仅用户发起 AI 操作时发送文本。配置不包含密钥，密钥由界面通过系统 keyring 管理。迁移时关闭应用并复制完整数据目录。

`complete(..., on_chunk=callback)` 启用 SSE 流式请求，逐段回调文本并返回合并结果；处理角色事件、结束标志、服务端错误和意外断流。所有界面模型调用均使用流式模式，包括概要、追问、翻译和连接测试。模型服务需支持 `stream: true`。

## 重启已有实例

启动脚本通过 Python 入口统一执行：识别同一工程目录中以 `python -m paperreader` 启动的旧进程，先请求终止，3 秒未退出再强制结束，确认退出后启动新窗口。不会按 Python 进程名批量结束其他程序。同时启动的重复请求由启动锁拦截。macOS 收到终止信号时尝试保存笔记；Windows 终止和超时强杀无法保证保存尚未落盘的内容，后台 AI 请求可能被中断。升级前启动的旧版本未包含保存信号处理，只能保留已自动保存内容。新增 psutil 依赖，旧环境先重跑安装脚本。

论文列表采用单行标题，超长省略、悬停显示全文，不再单列编号或来源。`services/titles.py` 优先读取 PDF 元数据，否则提取首页大字号标题；已有 arXiv 编号标题自动尝试修复。提取不准确时可双击论文列表项修改标题。

## 输入框内发送与多模型配置

追问使用纯文本输入，底部内嵌模型选择与发送按钮，文字编辑区域预留底部空间。模型设置可新增、命名、编辑、删除多个配置，每项独立保存 API 地址、模型名与系统密钥库账号；保存后可在输入框内切换。API 基础地址支持 HTTPS 和内网 HTTP，HTTP 请求会明文传输内容及已配置的密钥。至少保留一项配置，旧配置兼容到默认项并沿用原密钥。当前选择也供概要与翻译使用；请求期间禁用切换，已有历史不改写。切换模型不清除问题和引用。`services/profiles.py` 管理配置结构，`ui/composer.py` 管理内嵌控件布局。

## 问题导航与历史会话

论文追问标题中间显示居中问题导航点，点击跳到对应问答、悬停查看问题。数量过多时隐藏溢出，可用触控板左右滑动（也支持滚轮）查看。右侧“新建会话”开始独立对话，“历史”菜单查看当前论文的会话、时间和问题数量并切换。旧问答兼容迁移到首个会话；每个会话独立保存上下文，导出包含全部会话。请求期间暂不允许新建/切换，避免流式回复写错会话。新建和切换会清除未发送输入及引用，旧问答不会被删除。实现位于 `ui/questions.py` 与 `services/sessions.py`。

## 追问检索与引用

`retrieval.py` 按 PDF 文本块建立本地段落索引，保留页码和文字坐标。追问时用英文词、中文双字组合和常见论文术语排序，优先放入 PDF 选区及邻近段落。索引在首次追问时建立，当前论文打开期间复用。

模型接收当前请求的证据编号。回答中的有效编号显示为页码链接，点击跳到原文并临时高亮。引用随回答保存，加入笔记或导出时转成普通页码。旧回答没有段落坐标，仍按原样显示。

## 阅读助手与主题

默认深色主题的回答者显示为“无情的阅读机器”，模型请求使用中性表达指令，不注入人物设定。火影忍者主题显示“蛤蟆丸”，并在分析、追问和翻译请求中加入角色口吻设定。连接测试沿用简短测试请求。主题包将外观与助手绑定。新回答保留发起请求时的署名，旧回答缺少署名时沿用当前助手。

## 批量导入与移除

本地 PDF 导入支持多选，逐个处理并去重；单个文件失败会汇总提示，其余正常导入。论文列表右键“移除论文…”弹窗提供取消、仅从列表移除、彻底删除。仅移除保留记录，重新导入相同 PDF 可恢复。彻底删除应用资料库中的 PDF 副本及该论文全部笔记、概要、会话、问答、标注和阅读记录，清理内存草稿与公式缓存；源文件、已导出文件、外部备份和云端 API 服务商记录不在删除范围。删除当前论文时停止阅读保存定时器，避免旧记录复活；后台请求运行时暂不允许移除。彻底删除为应用级逻辑删除，不承诺存储介质取证擦除。

## 快速概要与精读报告

学习工作台顶部可选「快速概要」或「精读报告」，点击「阅读」开始。快速概要在预算内读取全文，长文节选首尾和重点章节。精读报告按段分析并汇总，每次完整模型输出保存为检查点。点击「停止」取消当前连接，保存已完成步骤和当前部分内容。底部的「继续阅读」按检查点恢复；顶部的「阅读」重新执行全部步骤。续读将当前部分内容的末尾带入原模型配置，要求模型从末尾接续。

模型设置中“最大输入长度”独立保存，默认50000字符，范围4096–2000000，包含提示词、历史与用户文本。字符不等于Token，需要按实际服务容量设置并预留输出。所有分段及汇总遵守上限；追问按剩余预算选择原文，必要时缩减旧对话，问题本身超限则提示。实现位于 services/analysis.py，无新增依赖。

## 按需加载论文

启动和刷新列表仅查询 paper_index 中的标题、来源与ID，不反序列化全文学习记录、不打开PDF。点击后按ID加载该篇PDF、笔记、报告与历史问答。已有资料库首次升级通过SQLite建立一次元数据索引，后续增删改同步维护；旧编号标题延迟到打开时识别。导入去重按ID查询，不再扫描所有记录；重命名与移除显式读取对应记录，避免用列表元数据覆盖完整内容。

## 启动依赖与耗时记录

`lazy.py` 将 PDF 引擎、HTTP 客户端和系统密钥库延迟到首次实际操作时导入，首次显示列表不加载这些组件及公式引擎。打包配置显式收集延迟依赖，保证独立 APP 可用。检查已有 APP 时先筛选进程名称，再读取可执行文件路径。每次正常启动在资料目录覆盖 `startup.json`，记录从 Python 入口到导入、旧进程处理、窗口创建和事件循环的累计秒数，不含论文或密钥。该记录不包含 macOS 在 Python 入口之前的应用检查与动态库加载时间。
